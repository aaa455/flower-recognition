# 测试集评估

模型训练与方案选择完成后，使用测试集评估最终效果。
验证集用于选择模型与调整方案；测试集不参与参数更新，也不用于反复调参。

```powershell
.\.venv\Scripts\python.exe -m src.evaluate --checkpoint runs/experiment-01/best.pt
```

脚本重建手写网络，加载权重、输入尺寸、训练集均值和标准差。
默认使用模型目录保存的 `manifest.csv`；通过 SHA-256 核对它与训练时的清单完全一致。
可以传入 `--manifest`，但内容必须与训练时完全一致；包括文件编码和换行变化也会导致核对失败。
这只核对清单内容，没有重新逐张核对图片文件，评估时应使用原始数据副本。

图片预处理不包含随机增强。使用 `model.eval()` 和 `torch.inference_mode()`，不更新参数或 BatchNorm 统计量。
测试加载器不打乱顺序、不舍弃末批，预测表中的图片路径与结果一一对应。

## 指标含义

- 准确率（accuracy）：全部测试图片中预测正确的比例。
- 精确率（precision）：预测为某类的图片中，真正属于该类的比例。
- 召回率（recall）：实际属于某类的图片中，被正确识别的比例，也就是该类内部的准确率。
- F1：精确率与召回率的调和平均值。
- 宏平均 F1（macro F1）：对五类 F1 等权平均，便于同时观察不同类别的表现。

例如有 10 张真正的玫瑰，正确识别 6 张，玫瑰召回率为 60%。
如果模型共预测出 8 张玫瑰，其中 6 张正确，玫瑰精确率为 75%。
分母为 0 时，报告将相应指标记为 0；因此需要结合 support（真实样本数）阅读结果。

## 混淆矩阵

行表示真实类别，列表示预测类别。对角线是预测正确的数量，其余位置显示类别混淆。
例如“玫瑰行、郁金香列”的数量，表示玫瑰被误识别为郁金香的图片数。
矩阵是原始数量，因此类别数量不同时，也要结合分类报告的召回率阅读。

## 输出文件

默认保存到模型目录下的 `test/`，可以用 `--output` 指定新的目录；已有目录不会覆盖。

| 文件 | 内容 |
|---|---|
| `metrics.json` | 测试准确率、宏平均 F1、模型轮次、验证准确率和划分哈希 |
| `classification_report.csv` | 每类真实样本数、精确率、召回率和 F1 |
| `confusion_matrix.csv` | 混淆矩阵原始数量 |
| `confusion_matrix.png` | 混淆矩阵图 |
| `predictions.csv` | 所有测试图片的路径、真实类别、预测类别和 softmax 分数 |
| `misclassified.csv` | 预测错误的图片记录 |

softmax 分数未经概率校准，高分不保证一定正确，也不能用于可靠判断未知花种。
模型只会在五类中选一个类别。
